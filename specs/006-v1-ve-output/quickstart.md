# Quickstart: V1/VE Output

## Goal

Verify the sixth executable PBGC engine slice: deterministic `v1_ve_output`
on top of the existing browser-side SQLite foundation and the implemented
date, service, compensation, form, and benefit-kernel slices.

## Prerequisites

- Repository is on the active V1/VE feature branch.
- Existing browser app, sql.js foundation, and the first five executable slices
  are present.
- Existing committed v0.1.0 contracts, schemas, migrations, seeds, templates,
  and V1/VE fixture content are present.

## Validation Flow

1. Start the browser app locally after implementation.
2. Confirm the existing sql.js foundation initializes from packaged static
   assets.
3. Apply or reuse the committed SQLite migrations and seeds already used by the
   prior slices.
4. Load the committed V1/VE fixture set and build the reviewed input packet for
   each supported case.
5. Run only the `v1_ve_output` module.
6. Verify persisted outputs:
   - one `engine_run` row per attempt
   - one `v1_ve_output_row` row per successful fixture
   - output fields populated or explicitly null according to expected fixture
     values
   - no valuation-listings or BSRS configuration rows generated by this slice
   - trace records for each populated V1/VE field and warning path
7. Re-run the same packet five times and verify populated values and trace
   decisions remain identical except generated identifiers and timestamps.
8. Attempt invalid packets and verify they fail before writing
   `v1_ve_output_row`.
9. Run date-resolution, service-resolution, compensation-resolution,
   form-resolution, and benefit-kernel regression tests to confirm prior slices
   still pass.
10. Keep the prior-slice regression guard in place whenever V1/VE validation or
    packet-shape rules change.

## Out of Scope Checks

Do not run valuation listings, BSRS configuration, or other output-adapter
logic in this slice.

## Completion Criteria

- Committed V1/VE fixtures pass.
- Invalid V1/VE packet checks are blocked with structured errors.
- Trace exists for every populated V1/VE output field.
- Conditional branch cases preserve explicit null output values.
- Existing date-resolution, service-resolution, compensation-resolution,
  form-resolution, and benefit-kernel tests still pass.
- No network connection is required for deterministic execution.
- Static build output is committed when implementation changes runtime assets.
